### The gate

`WolkaraForeverInterfaceModeV1` (in `wolkaraforever/Touch/InterfaceMode.h`) is read on every
use. `ios` is the mobile interface; a missing, `ipados`, or hand-edited value is Standard.
Gated paths, each asserted in both modes by a fixture:

| Path | Standard (v1.0.7) | Mobile |
| --- | --- | --- |
| Toolbar | 252×44, top, five buttons, always open, no handle | 96×34 folded at the bottom centre, keyboard only, auto-collapse |
| Keyboard's return key | Done replaces the selected field | Send puts the line in the chat (F12, text, Return) |
| Trackpad default | the platform's (on for a phone, off for an iPad) | off |
| Gamepad | every button, menu above the bottom edge, sheet from the bottom | sticks and jump, Space jump, 1.4-ring reach, menu above the toolbar, sheet from the top |
| Host multi-touch | several fingers exactly while the trackpad is on; no pinch recognizer | several fingers always; the pinch follows the trackpad |
| Direct touch | a finger is a left click | tap, hold-then-right-click, drag, pinch |
| Draft placeholder | "Draft · Replaces the field; empty clears it" | "Return sends to the chat · Replace writes into the selected field" |

### Defects the fixtures found while gating

- `pointInside:` built an array literal that included the toolbar handle, which is nil in
  Standard: every touch on a Standard guest aborted. Found by `test_translation_sim.sh` on the
  iPad simulator, fixed before the first build was offered.
- v1.0.7's `_controllerArrived` guard was missing from the contributor's `TouchGamepad.m`, so
  the settings panel closed on any window notification again. Found by the gamepad lifecycle
  fixture, restored.
- The contributor's tables lacked `shell.repairRequired.*` and `home.download.remaining`, so
  the launcher's download line read "· Remaining" and the repair sentence was unobtainable.
  Found by the launcher fixture and `check_localization.py`, restored and translated.
