## The live-app guard

`install.sh` and `pilot.sh` matched any `Tolkara.app/Tolkara` process on the
device. With the pre-rename bundle and the new bundle installed side by side,
that made an install of one refuse because the other was running, and a forced
stop could signal the wrong app. `wolkaraforever/tools/running_app.sh` resolves
the target bundle's installation path from devicectl's catalogue and matches
only a process inside that container; if the catalogue cannot be read it keeps
the old, conservative match.

```
Command: wolkaraforever/tools/tests/test_running_app.sh
ok   the target bundle's own process is found, and its plugin is not
ok   another Tolkara build running is not this bundle
ok   nothing running when no Tolkara process is up
ok   a bundle that is not installed has nothing to replace
ok   an unreadable catalogue falls back to the conservative match
ok   an unparsable installation path falls back to the conservative match
RUNNING_APP_PASS: bundle-aware guard, side-by-side builds, plugins and
conservative fallback.
```

Against the device, the helper reports no pid for `local.wolkara.johnklock`
(not running) and the new bundle's pid for `local.wolkaraforever.johnklock`,
so the install of the game-bearing bundle proceeded without touching the other
app.
