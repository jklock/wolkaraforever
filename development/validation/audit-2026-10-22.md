# Full audit: 2026-10-22 (commit `fe06cba`)

Scope: the whole layer as shipped on this branch, with particular attention to
the places where behaviour depends on app identity, containers, Keychain groups
and defaults — the class of defect that broke the game launch after the data
move.

## Method

1. Repository hygiene: working tree, stray temporary code and files, tracked
   secrets, device identifiers, ignored-but-required settings.
2. Read the code paths for the home page, Forever UI config and archive,
   add-on key/client, overlay, install/pilot guards.
3. Run every host and simulator suite, then the full validation runner on a
   clean commit.
4. Install that commit on the iPad, run the on-device self-tests, launch the
   game, and leave the device on its home screen.

## Findings fixed

| Finding | Fix | Evidence |
| --- | --- | --- |
| `CurseForgeClient.m` gained a direct import of the app target's log header, breaking the standalone CurseForge contract test | Logging is conditional on `__has_include`; the layer compiles without the app target | `test_curseforge.sh` PASS |
| Restore's picker delegate trusted a pending flag only, so a stale flag could interpret an add-on folder choice as a restore | The picker's own `directoryURL` must also match the stored backups folder | launcher fixture PASS |
| The live-app guard treated "installed, but the catalogue gave no path" as "nothing running" | Falls back to the conservative match, as for an unreadable catalogue; test added | `test_running_app.sh` PASS (7 cases) |
| The archive trusted manifest paths without checking them, and accepted a symlink as the selected backup | Manifest paths must be inside `WTF`/`Interface`, unique, case-insensitively; the selected backup must be a regular file | Forever UI archive suite PASS (37 checks) |
| An uninstall removes `TKEnrolledDeviceIdentifier` while the Keychain enrollment survives, with no recovery path in the product | `--selftest=enrolled-device` restores it from `TK_DEVICE`; documented | device self-test PASS 2/2 |

## Accepted or residual, with reasons

- **Developer-service enrollment prints `EOFError` on install.** It uses the
  system's trusted USB bridge, which cannot see a Wi-Fi-only device. It is not
  needed here: the enrollment made for the earlier bundle survives in the
  Keychain and is read through the group recorded in `local.env`. The install
  still completes and the game launches.
- **Reinstall after an uninstall** loses the enrolled-device default again. The
  Keychain record survives; restore the pointer with
  `DEVICECTL_CHILD_TK_DEVICE=<UDID> devicectl ... --selftest=enrolled-device`.
- **Render reads `Config.wtf` for the gamepad switch while the rows are usable.**
  A few kilobytes, page-cached; it is skipped while the app is busy. A caching
  refinement, not a correctness fault.
- **Add-on installation is limited to TOCs declaring interface 16001.** That is
  the measured Forever mapping, and the installer says so; other editions are
  browse-only by design.
- **The platform's ad-hoc signer is not byte-identical to this macOS's
  `codesign`.** Reproduced without the layer; on the known-failure list with
  evidence. Local signing needs a valid signature, which it has.
