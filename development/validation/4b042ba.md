## CurseForge key

`AddonCredentialStore` treated every key beginning `$2a$` as a password hash and
refused it. CurseForge's approved Core API keys are issued in exactly that
bcrypt shape, so an approved key never reached the network. Only the upload
personal-access token prefix (`cfc_pat_`) is refused now, with a message that
names it.

The key supplied for the approved Wolkara-Connect application was checked
directly against the API, and is not written anywhere in this repository:

```
$ curl -H "x-api-key: <approved key>" https://api.curseforge.com/v1/games/1
HTTP 200
game: World of Warcraft
id: 1
```

The fixture also proves the store's decision: a key of the same shape is not
refused as the wrong kind (only the Keychain may refuse it on the host), and an
upload token still is. The key has to be entered again in Browse CurseForge,
because the refused one was never stored.
