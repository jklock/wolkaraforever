# UI review: the launcher mark reaches the baseline fixtures

## Classification

`test-harness-and-baseline`. No launcher surface is redesigned: every identifier, string, row,
card, order, colour, and geometry contract in `UI_POLICY.md` stays exactly as v1.0.10 shipped
it. What changes is that the reviewed images now contain the artwork the app actually draws,
and the fixture fails when the artwork is not in the build.

## What was wrong

The home page's identity mark is `-[WoWViewController markView]`
(`wolkaraforever/WoW/WoWViewController.m`): it draws `WolkaraForeverLogo` from the asset catalog
and falls back to a gold serif `WOLKAREFOREVER` wordmark only when that image is not in the
bundle.

`wolkaraforever/tools/test_wow_launcher_ui.sh` built `WoWFixture.app` with `clang` from the
launcher's `.m` files and copied in the four licence documents and the `en`/`de` tables - and no
asset catalog. `xcrun simctl get_app_container` on the iPhone Duo showed the installed fixture
bundle as:

```text
Info.plist  LICENSE  NOTICE.md  WoWFixture  _CodeSignature  de.lproj  en.lproj
```

So `imageNamed:@"WolkaraForeverLogo"` was nil in every fixture run, the wordmark was drawn, and
all 17 reviewed baselines captured the fallback. The fixture's own assertion was an OR -
`Find(view,@"wow.logo") || Find(view,@"wow.title")` - so a build that had lost the artwork would
have passed the matrix exactly like one that had it.

Measured for comparison on the installed app: `TolkaraDiagnostics.app`'s `Assets.car` lists
`"Name" : "WolkaraForeverLogo"`, and a live launch draws it (iPad Pro 12.9-inch, 2026-11-12).

## What changes

1. `test_wow_launcher_ui.sh` compiles `launcher/Assets.xcassets` with `actool` into the fixture
   bundle before signing it, and fails if no `Assets.car` is produced.
2. `test_wow_launcher_app.m` asserts `wow.logo` in both places it used to accept
   `wow.logo || wow.title`.
3. The 17 baselines for each matrix simulator are re-recorded from the fixture that now draws
   the artwork. The comparator, its tolerance, the state list, and the layout contract are
   unchanged.
4. `LAUNCHER_UI_BASELINE.md` states what the mark is, and its required-state list is corrected:
   it named a `wow-addons-recommended-macever.png` that no device directory has ever contained.

## Exact SHA

The commit that carries this record on `main`; the baselines, the fixture and this file are in
that one commit.

## End-user action

None. The app's behaviour is unchanged; the matrix's claim about it is what changes. It now
proves the artwork renders, and a build without it fails.

## Risks and boundary

- The header area of every baseline changes (the mark is taller than the wordmark line). Both
  matrix simulators were re-recorded and the images are committed with this record.
- The fixture now needs `actool`, which ships with the same Xcode the matrix already requires
  (`xcrun clang`, `xcrun simctl`). A missing `actool` fails loudly instead of silently falling
  back to the wordmark.
- The device path is untouched: the installed app already carried the catalog.
- `docs/screenshots/launcher-home.jpg` is re-shot from the installed app rather than the
  simulator, so the guide shows what a user sees.
